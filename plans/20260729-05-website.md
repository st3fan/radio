# Plan: Website v1 (milestone 5)

The second component: a plain PHP site in `website/` that lists the SomaFM
channels and controls the daemon. Functional and unstyled — forms and
full-page reloads; styling and JS niceties are milestone 7. Single PR
against `main`.

## Constraints recap (from notes/plan.md / CLAUDE.md)

- Plain PHP, no framework, no Composer dependencies. Target is whatever
  Debian ships (PHP 8.2 on bookworm); use only core + standard extensions
  (`json`; HTTP via stream contexts so we don't even need php-curl).
- The browser never talks to the daemon: every daemon call happens
  server-side against `127.0.0.1:8080`.
- Dev serving via `php -S`; production web server setup is milestone 6.

## Layout

```
website/
  public/
    index.php       the one page: status panel + controls + channel list
  lib/
    config.php      daemon URL, cache path/TTL
    daemon.php      client for the radiod API (stream-context HTTP)
    somafm.php      channels.json fetch + disk cache
  README.md         how to run it (php -S), what it needs
```

`public/` is the docroot (`php -S 0.0.0.0:8000 -t website/public`), so
`lib/` is never directly reachable from the browser.

## SomaFM channel list (`somafm.php`)

- Fetch `https://api.somafm.com/channels.json` server-side; cache the raw
  JSON on disk (`sys_get_temp_dir()/radio-channels.json`) with a 5-minute
  TTL so we do not hammer SomaFM and pages stay fast.
- If the fetch fails and a stale cache exists, serve stale (log a notice);
  if there is no cache at all, show an error row instead of a channel list.
- Per channel we use: `id`, `title`, `description`, `genre`, `listeners`,
  and `playlists`. The playlist URL to hand to the daemon is the entry
  with `format == "mp3"` and `quality == "highest"`, falling back to the
  first mp3 entry, then to `https://somafm.com/{id}.pls`. (Verified
  against the live API: 46 channels, each with exactly this structure.)
- Channels sorted by `listeners` descending — most popular on top.

## Daemon client (`daemon.php`)

Thin functions over the REST API using `file_get_contents` with a stream
context (POST + JSON body, 1 s connect timeout so a dead daemon does not
hang the page): `radio_status()`, `radio_play($playlist_url)`,
`radio_stop()`, `radio_pause()`, `radio_resume()`, `radio_volume($pct)`,
`radio_mute()`, `radio_unmute()`. Each returns the decoded JSON (or an
`error` shape). Non-2xx responses are surfaced, not hidden — the 409 from
`/pause` while stopped becomes a visible message.

## The page (`index.php`)

- **POST-redirect-GET**: all actions are `<form method="post">` posting to
  `index.php`; after performing the action the page 303-redirects to
  itself so refresh never repeats an action. Action results (e.g. an error
  from the daemon) travel via a short-lived query parameter.
- **Status panel** (top): state, station (`icy_name`), now playing
  (`icy_title`), effective volume / max, muted. Plus the control forms:
  pause/resume, stop, mute/unmute, and a volume form — a number input
  0–100 labeled as **percent of the maximum** (matching the API
  semantics).
- **Channel list**: one row per channel — title, genre, description,
  listener count, and a **Play** button (form with the channel id; the
  server looks up the playlist URL from the cached channel data rather
  than trusting a URL from the form). The currently playing channel is
  marked.
- If the daemon is unreachable: the status panel says so plainly and the
  channel list still renders.
- All output through `htmlspecialchars` — channel descriptions and ICY
  titles are external data.

## Testing

- `php -l` on every file (there is no test framework in v1; the logic that
  deserves tests — playlist selection, cache TTL — is small and isolated
  in `lib/`, and we can add PHPUnit later if the site grows).
- Manual on the Mac: daemon with `--sink null`, `php -S`, exercise every
  button and the daemon-down case.
- Acceptance on the Debian PC (the real thing): browse to the site from
  the Mac, pick a channel → music from the speakers; now-playing shows
  and updates on reload; pause/resume/stop/volume/mute all work from the
  browser; stale-cache behavior verified by blocking somafm.com briefly.

## Out of scope (later milestones)

- Styling, channel artwork, auto-refreshing now-playing (milestone 7).
- Production web server + php-fpm setup, running on the Pi (milestone 6).

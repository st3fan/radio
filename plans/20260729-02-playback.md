# Plan: Playback (milestone 2)

Make `radiod` actually play radio: `POST /play` with a `.pls` playlist URL
streams audio to the configured output, `POST /stop` stops it. Decoding via
the FFmpeg libraries (`ffmpeg-next`), output through an `AudioSink` trait
with the ALSA implementation Linux-only and dev sinks for macOS.

This is the largest milestone, so it is split into **three phases, each its
own PR**, on an integration branch `integration/milestone-2-playback` (per
CLAUDE.md). When phase 3 is done the integration branch merges to `main`.

Out of scope (later milestones): ICY metadata in `/status`, `/pause` /
`/resume`, `/volume` / `/mute` / `/unmute`, reconnect-with-backoff polish,
systemd/cross-compilation. Volume stays fixed at `initial_volume` for now —
but every sample already passes through `volume::gain()`.

## Architecture

```
HTTP handler ── PlayerCommand over mpsc channel ──▶ player thread
                                                      │ owns the pipeline:
   /play resolves the .pls (ureq) in the handler      │ ffmpeg input → decode
   so bad playlists fail the request synchronously    │ → resample to s16
                                                      │ → gain (volume::gain)
   Arc<Mutex<Status>> shared: handler reads,          │ → AudioSink
   player thread writes state transitions             ▼
                                              alsa | wav | null sink
```

- **Player thread** (spawned at startup, lives forever): blocks on the
  command channel when idle; while playing, polls `try_recv()` between
  packet reads so `Stop`/`Play` interrupt within one packet (~tens of ms).
- **Commands**: `Play { playlist_url, stream_url }`, `Stop`. A new `Play`
  while playing tears down the current pipeline first (station switching).
- **Status transitions** owned by the player thread: `stopped → playing` on
  successful open, back to `stopped` on `Stop`, end of stream, or fatal
  error (logged; retry/backoff is milestone 4). `playlist_url` and
  `stream_url` are set while playing, cleared on stop.

## The `AudioSink` trait

```rust
pub struct AudioSpec { pub rate: u32, pub channels: u16 }

pub trait AudioSink {
    fn open(&mut self, spec: AudioSpec) -> Result<(), SinkError>;
    fn write(&mut self, frames: &[i16]) -> Result<(), SinkError>;  // interleaved
    fn close(&mut self);
}
```

Implementations:

- `AlsaSink` — `#[cfg(target_os = "linux")]`, `alsa` crate, opens
  `config.audio_device` (`plughw:...` so ALSA converts rate/format).
- `WavSink` — writes a WAV file (header written on `close`); dev sink for
  listening to pipeline output on macOS. Hand-rolled header, no new crate.
- `NullSink` — discards frames; keeps tests and CI silent and fast.

Selection: `alsa` is the default on Linux, `null` elsewhere; a dev-only
`--sink null|wav:<path>|alsa` flag overrides. **Gain is applied by the
pipeline before frames reach any sink** — sinks never touch levels, so the
clamp stays in exactly one place, and a capturing test sink can assert on
the actual samples written.

## Pipeline (player thread, per station)

1. `.pls` already resolved by the handler → stream URL.
2. `ffmpeg_next::format::input_with_dictionary(stream_url, opts)` with
   `reconnect=1`, `reconnect_streamed=1`, `reconnect_delay_max=10`,
   `user_agent=radiod/<version>`.
3. Best audio stream → decoder context.
4. `software::resampling::Context` to packed `s16`, keeping the source's
   rate and channel layout (the sink is told via `AudioSpec`; `plughw`
   handles device-side conversion).
5. Per resampled frame: `apply_gain(samples, volume::gain(volume, muted))`
   (i32 multiply with clamping, in `volume.rs`, unit-tested) → `sink.write()`.

## HTTP API changes

| Method & path | Body | Effect |
|---------------|------|--------|
| `POST /play`  | `{"playlist_url": "https://…/defcon.pls"}` | Fetch + parse the playlist in the handler (400 malformed body, 502 fetch/parse failure), send `Play` to the player, return the full status JSON. |
| `POST /stop`  | — | Send `Stop`, return the full status JSON. |

Note: `/play` returns as soon as the command is queued; the stream open
happens on the player thread, so `state` in the response may still be
`stopped` for a moment. Fine for milestone 2; the website polls `/status`.

## Phases

### Phase 1 — sinks, player thread, endpoints (no FFmpeg)

- `sink.rs`: trait + `NullSink` + `WavSink` (+ a capturing `TestSink` in
  test code).
- `player.rs`: thread, command channel, status transitions.
- `apply_gain()` in `volume.rs`.
- `pls.rs`: fetch (`ureq`) + parse (`File1=` etc., case-insensitive,
  first `FileN` wins); unit tests against SomaFM-shaped fixtures.
- `/play` + `/stop` routed; a built-in test source (440 Hz sine, i16) plays
  into the sink so the whole flow is exercisable before FFmpeg exists:
  `--sink wav:out.wav` + `/play` + `/stop` yields a WAV with a clean,
  gain-scaled tone in it.
- Tests: pls parsing, gain application via capturing sink, player state
  transitions, routing.

New dependency: `ureq`.

### Phase 2 — FFmpeg decode pipeline (macOS + WAV sink)

- Add `ffmpeg-next`; document build prerequisites in `service/README.md`
  (macOS: `brew install ffmpeg pkg-config`; Debian: `apt install clang
  libavformat-dev libavcodec-dev libavutil-dev libswresample-dev`).
- `pipeline.rs`: open/decode/resample as above; replaces the phase-1 sine
  source for `/play` (the sine source stays available to tests).
- End of stream / decode errors → log, transition to `stopped`.
- Acceptance on the Mac: `/play` with `https://somafm.com/defcon.pls` and
  `--sink wav:out.wav` produces a WAV that plays actual DEF CON Radio audio,
  scaled by the initial volume; `/stop` ends it cleanly; station switch
  (second `/play`) works.

New dependency: `ffmpeg-next`.

### Phase 3 — ALSA sink and real hardware (Debian PC)

- `AlsaSink` behind `#[cfg(target_os = "linux")]` using the `alsa` crate:
  open `config.audio_device`, set hw params (s16, spec rate/channels),
  handle underruns by `prepare()` + continue.
- Cargo: `alsa` as a Linux-only target dependency.
- Verify on the Debian PC over SSH, speakers connected: `/play` →
  music at a sane (clamped) level, `/stop` → silence, station switch works,
  and `cargo test`/`clippy`/`fmt` are green on Linux too.
- Document the Debian run steps in `service/README.md`.

New dependency: `alsa` (Linux only).

## Acceptance (milestone level)

- All phase tests green on macOS *and* Linux; clippy/fmt clean on both.
- On the Debian PC: `POST /play` (defcon.pls) plays through the speakers at
  the gain implied by `initial_volume`/`max_volume`; `/status` shows
  `playing` with both URLs; `POST /stop` silences; switching stations with
  a second `/play` works without restart.
- A capturing-sink unit test proves peak sample amplitude ≤
  `max_volume/100 × i16::MAX` for a full-scale input — the invariant holds
  end to end.

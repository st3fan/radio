# Plan: PWA / add-to-homescreen (milestone 8)

Make the site installable on Stefan's iPhone homescreen as a chrome-less
app. iPhone-only by decision, which sets the scope: iOS adds any
same-origin HTTP site to the homescreen — no TLS, no service worker
(iOS gates those behind HTTPS anyway). Single PR against `main`.

## What we add

- **`public/manifest.webmanifest`**: `name`/`short_name` RADIO,
  `display: standalone`, `start_url: /`, `background_color`/`theme_color`
  `#050805` — launching from the homescreen gets the terminal, no Safari
  chrome, black to the edges.
- **Icons, pixel-art phosphor**: drawn as a pixel grid from an ASCII-art
  map by a small dev-time script (`deploy/make-icons.php`, PHP GD — a
  blocky green "R" with a cursor block on `#050805`). Generated PNGs are
  committed so package builds never need GD: `icon-180.png`
  (apple-touch-icon), `icon-192.png`, `icon-512.png` (manifest, one
  maskable with safe-zone padding).
- **Head additions in `index.php`**: manifest link, `apple-touch-icon`,
  `theme-color`, `apple-mobile-web-app-title`, status-bar meta
  (`black-translucent`), and `viewport-fit=cover` with
  `env(safe-area-inset-*)` padding in the CSS so the terminal respects
  the notch/home-indicator in standalone mode.
- The `radio-website` package ships the new files; version bump to
  `0.3.0-1`.

## Why nothing more (the "other PWA things" audit)

- **Service worker / offline page**: requires a secure context; the site
  is plain HTTP on the LAN. The offline story without it is Safari's
  error page — acceptable for a remote control that is useless offline
  anyway. Revisit only if the Pi ever grows HTTPS.
- **Media Session / lock-screen controls**: not applicable — the audio
  plays on the Pi, not the phone; the phone is a remote, and iOS only
  offers lock-screen controls for audio the page itself plays.
- **Manifest shortcuts** (long-press icon → quick actions): Android-only;
  iOS ignores them.
- **Web push** (song-change notifications): iOS supports it for installed
  PWAs, but only over HTTPS and with real push infrastructure. Future
  idea at most.

What standalone mode *does* give us beyond the icon: full-screen
terminal with the status bar blending into the black, app-switcher
presence, and — thanks to milestone 7's poller — a now-playing display
that stays current without the reload button Safari no longer shows.

## Acceptance

- On the iPhone: Share → Add to Home Screen shows the phosphor icon and
  the name RADIO; launching opens full-screen (no Safari UI), black into
  the status bar, controls and live song titles working; safe-area
  padding correct in portrait and landscape.
- Desktop browsers: unchanged appearance, no console errors from the new
  head tags.
- `apt install` of 0.3.0-1 upgrades the site in place.

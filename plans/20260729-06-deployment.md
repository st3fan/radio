# Plan: Deployment (milestone 6)

Get Radio onto the Pi Zero W: a cross-compiled `radiod`, a systemd unit,
the website served by lighttpd + php-fpm, and repeatable install steps.

Three phases on an integration branch `integration/milestone-6`. Phase 1
(the cross-compile) is the risk; it gets proven on hardware before
anything else builds on it.

## Assumptions to confirm before phase 1

- The Pi runs 32-bit Raspberry Pi OS (Bookworm assumed → FFmpeg 5.1,
  PHP 8.2, libasound2). `cat /etc/os-release` and `apt list --installed
  'libav*'` tell us; `ffmpeg-next` compiles against 3.4–8.0 so any recent
  release works, but the sysroot must come from the OS actually installed.
- The Pi is reachable over SSH from the Debian PC (for rsyncing the
  sysroot and copying builds).

## Phase 1 — ARMv6 cross-compile

Target `arm-unknown-linux-gnueabihf` (ARMv6+VFP2 — the Pi Zero W 1 cannot
run Debian's ARMv7-tuned armhf binaries, which is also why we do not just
`apt install rust` on a Debian box and copy things over).

Approach: build on the **Debian PC**, linking against a **sysroot rsynced
from the Pi itself** — that guarantees the exact sonames and symbol
versions of the libraries radiod will find at runtime:

1. On the Pi: `apt install libavformat-dev libavcodec-dev libavutil-dev
   libswresample-dev libasound2-dev` (dev packages so the sysroot has
   headers and `.pc` files).
2. On the Debian PC: `rustup target add arm-unknown-linux-gnueabihf`,
   `apt install gcc-arm-linux-gnueabihf clang`, then
   `rsync` `/usr/include`, `/usr/lib/arm-linux-gnueabihf`,
   `/lib/arm-linux-gnueabihf` from the Pi into e.g. `~/pi-sysroot/`.
3. A `service/build-pi.sh` script wires it together:
   - `CARGO_TARGET_ARM_UNKNOWN_LINUX_GNUEABIHF_LINKER=arm-linux-gnueabihf-gcc`
   - `RUSTFLAGS="-C link-arg=--sysroot=$SYSROOT"`
   - `PKG_CONFIG_SYSROOT_DIR=$SYSROOT`, `PKG_CONFIG_LIBDIR=$SYSROOT/usr/lib/arm-linux-gnueabihf/pkgconfig:$SYSROOT/usr/share/pkgconfig`
   - `BINDGEN_EXTRA_CLANG_ARGS="--sysroot=$SYSROOT -I$SYSROOT/usr/include"`
   - `cargo build --release --target arm-unknown-linux-gnueabihf`
4. Documented fallback if the sysroot route fights back: a qemu-emulated
   ARMv6 container build (slow but simple). Decision stays with whatever
   works first; the script is the deliverable either way.

Acceptance: the binary runs on the Pi (`./radiod -v`, then `/play` with
the null sink absent — real ALSA — and music comes out), and a CPU
check while playing (`top`): decode + resample on the ARM1176 expected
well under 50%; if it is not, we revisit (release profile, `opt-level`,
or buffer sizes) before proceeding.

## Phase 2 — daemon install: systemd + config

New top-level `deploy/` directory:

```
deploy/
  radiod.service        systemd unit
  config.toml.example   documented config for the Pi
  install-radiod.sh     copies binary + unit + config into place (run on the Pi)
```

- Unit: `After=network-online.target` + `Wants=`, `Restart=always`,
  `RestartSec=5`, runs as a dedicated system user `radio` in the `audio`
  group, binary at `/usr/local/bin/radiod`, config `/etc/radio/config.toml`
  (`--config` flag). Modest hardening: `NoNewPrivileges`, `ProtectSystem=full`,
  `ProtectHome`, `PrivateTmp`.
- Config: `audio_device` from `aplay -l` on the Pi, `max_volume`
  deliberately left at the default 50 unless Stefan sets it.
- The daemon keeps stderr logging; `journalctl -u radiod` is the log.

Acceptance: reboot the Pi → radiod is up, `/status` answers on loopback;
kill -9 the daemon → systemd restarts it within seconds; music survives a
reboot in the sense that the service is controllable immediately after.

## Phase 3 — website serving + end-to-end

- lighttpd + php8.x-fpm (lighter than nginx; both in Raspberry Pi OS).
  Site files installed to `/var/www/radio/` (`public/` as docroot, `lib/`
  beside it, outside the docroot). lighttpd listens on port 80 on the LAN
  interface — the site is the one thing that is *supposed* to be reachable
  from the network.
- php-fpm pool sized for the Pi: `pm = static`, `pm.max_children = 2`
  (512 MB total, and the daemon needs its share).
- `deploy/` grows: `lighttpd-radio.conf`, `install-website.sh`.
- A top-level `README.md` for the repo: what this is, the architecture
  diagram, and pointers to the install steps (the current stub only says
  "radio").

Acceptance (the milestone finish line): from a browser on the Mac, open
`http://<pi>/`, pick a channel — music from the studio speakers, driven
entirely by the Pi. Reboot the Pi: everything comes back by itself.
Then let it play for an evening — memory (`radiod` RSS) and CPU stay flat.

## Out of scope

- TLS, auth (LAN-only office device).
- Auto-updates/CI artifacts — builds are made on the Debian PC by hand
  via `build-pi.sh` for now.
- Styling/auto-refresh (milestone 7).

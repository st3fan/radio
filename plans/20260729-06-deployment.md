# Plan: Deployment (milestone 6)

Get Radio onto the Pi Zero W as **two Debian packages**: `radiod`
(cross-compiled, with systemd unit and config) and `radio-website`
(lighttpd + php-fpm site). Install and upgrade via `apt install ./<deb>`,
which also pulls the runtime dependencies (libav*, libasound2, lighttpd,
php-fpm) automatically.

Three phases on an integration branch `integration/milestone-6`. Phase 1
(the cross-compile) is the risk; it gets proven on hardware before
anything else builds on it.

## Facts (confirmed by Stefan)

- The Pi runs **Debian Trixie** (as reported by the OS — on a Pi Zero W 1
  this is the Raspberry Pi OS ARMv6-hardfloat build of trixie, since
  stock Debian armhf is ARMv7-only and cannot run on the Zero's ARM1176).
  Trixie means FFmpeg 7.x libraries and PHP 8.4. `ffmpeg-next` compiles
  against FFmpeg 3.4–8.0, so 7.x is fine.
- The Pi is reachable over SSH (sysroot rsync, copying packages).
- Quick sanity checks at the start of phase 1: `uname -m` on the Pi
  (expect `armv6l`), `dpkg --print-architecture` (expect `armhf` — that
  is also the .deb architecture name we ship), and the exact libav*
  package names/sonames (`apt list --installed 'libav*'`) for the
  package's Depends line.

## Phase 1 — ARMv6 cross-compile

Target `arm-unknown-linux-gnueabihf` (ARMv6+VFP2 — the Pi Zero W 1 cannot
run Debian's ARMv7-tuned armhf binaries, which is also why we do not just
`apt install rust` on a Debian box and copy things over).

Approach: build on the **Debian PC**, linking against a **sysroot rsynced
from the Pi itself** — that guarantees the exact sonames and symbol
versions of the libraries radiod will find at runtime:

1. On the Pi: `apt install libavformat-dev libavcodec-dev libavutil-dev
   libswresample-dev libasound2-dev` (dev packages so the sysroot has
   headers and `.pc` files).
2. On the Debian PC: `rustup target add arm-unknown-linux-gnueabihf`,
   `apt install gcc-arm-linux-gnueabihf clang`, then
   `rsync` `/usr/include`, `/usr/lib/arm-linux-gnueabihf`,
   `/lib/arm-linux-gnueabihf` from the Pi into e.g. `~/pi-sysroot/`.
3. A `service/build-pi.sh` script wires it together:
   - `CARGO_TARGET_ARM_UNKNOWN_LINUX_GNUEABIHF_LINKER=arm-linux-gnueabihf-gcc`
   - `RUSTFLAGS="-C link-arg=--sysroot=$SYSROOT"`
   - `PKG_CONFIG_SYSROOT_DIR=$SYSROOT`, `PKG_CONFIG_LIBDIR=$SYSROOT/usr/lib/arm-linux-gnueabihf/pkgconfig:$SYSROOT/usr/share/pkgconfig`
   - `BINDGEN_EXTRA_CLANG_ARGS="--sysroot=$SYSROOT -I$SYSROOT/usr/include"`
   - `cargo build --release --target arm-unknown-linux-gnueabihf`
4. Documented fallback if the sysroot route fights back: a qemu-emulated
   ARMv6 container build (slow but simple). Decision stays with whatever
   works first; the script is the deliverable either way.

Acceptance: the binary runs on the Pi (`./radiod -v`, then `/play` with
the null sink absent — real ALSA — and music comes out), and a CPU
check while playing (`top`): decode + resample on the ARM1176 expected
well under 50%; if it is not, we revisit (release profile, `opt-level`,
or buffer sizes) before proceeding.

## Phase 2 — the `radiod` .deb (cargo-deb)

Use **`cargo-deb`** (`cargo install cargo-deb` on the Debian PC): it
builds a proper .deb from `[package.metadata.deb]` in Cargo.toml and has
first-class systemd support. `service/build-pi.sh` grows a packaging step:
`cargo deb --target arm-unknown-linux-gnueabihf` (reusing the phase-1
sysroot environment) → `radiod_0.1.0-1_armhf.deb`.

Package contents and behavior:

- `/usr/bin/radiod` (release build, stripped).
- `deploy/radiod.service`: `After=network-online.target` + `Wants=`,
  `Restart=always`, `RestartSec=5`, runs as the dedicated system user
  `radio` (member of `audio`), `--config /etc/radio/config.toml`. Modest
  hardening: `NoNewPrivileges`, `ProtectSystem=full`, `ProtectHome`,
  `PrivateTmp`. Registered via cargo-deb's `systemd-units` feature, which
  generates the enable/start-on-install and stop-on-remove scriptlets.
- `/etc/radio/config.toml` marked as a **conffile** — documented example
  content (`audio_device` from `aplay -l` on the Pi, `max_volume` left at
  the default 50); apt upgrades never clobber Stefan's edits.
- A `postinst` fragment creates the `radio` system user and adds it to
  `audio` (maintainer scripts live in `deploy/debian/`).
- `Depends:` written explicitly with the package names read off the Pi
  (trixie: `libavformat61`, `libavcodec61`, `libavutil59`,
  `libswresample5`, `libasound2`, plus libc — exact list confirmed in
  phase 1). cargo-deb's `$auto` shlibdeps does not work reliably for
  cross builds, so we pin the list and keep it next to the sysroot notes.
- Logs stay on stderr → `journalctl -u radiod`.

Acceptance on the Pi: `apt install ./radiod_*.deb` pulls the libav*/alsa
dependencies and starts the service; `/status` answers on loopback;
`kill -9` → systemd restarts it within seconds; reboot → it is up without
intervention; `apt purge radiod` removes cleanly (config asked about, user
policy per Debian convention); reinstall works.

## Phase 3 — the `radio-website` .deb + end-to-end

- **`radio-website_0.1.0-1_all.deb`**, staged with plain `dpkg-deb --build`
  by `deploy/build-website-deb.sh` (no cargo involvement; arch `all`):
  - `/var/www/radio/public` (docroot) and `/var/www/radio/lib` (outside
    the docroot).
  - `/etc/lighttpd/conf-available/90-radio.conf` — docroot + php-fpm
    fastcgi wiring; enabled in postinst via `lighty-enable-mod`.
  - php-fpm pool config sized for the Pi: `pm = static`,
    `pm.max_children = 2` (512 MB total, and the daemon needs its share).
  - `Depends: lighttpd, php-fpm, php-cli` (trixie's php8.4-fpm via the
    meta package so the package survives PHP version bumps).
  - postinst reloads lighttpd/php-fpm; prerm disables the site config.
- lighttpd listens on port 80 on the LAN — the site is the one thing that
  is *supposed* to be reachable from the network.
- A top-level `README.md` for the repo: what this is, the architecture,
  build-and-install steps (the current stub only says "radio").

Acceptance (the milestone finish line): `apt install` both debs on a
freshly rebooted Pi; from a browser on the Mac open `http://<pi>/`, pick a
channel — music from the studio speakers, driven entirely by the Pi.
Reboot: everything comes back by itself. Then let it play for an evening —
`radiod` RSS and CPU stay flat.

## Out of scope

- TLS, auth (LAN-only office device).
- An apt repository / CI-built artifacts — the two .debs are built on the
  Debian PC by hand via the build scripts for now; scp + `apt install
  ./<deb>` is the distribution mechanism.
- Styling/auto-refresh (milestone 7).

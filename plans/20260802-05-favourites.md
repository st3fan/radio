# Plan: favourite stations

- **Date:** 2026-08-02
- **Status:** draft

## Background

Seven clicks of scrolling to get back to Drone Zone every morning is
silly (`notes/ideas.md`, "Favorite stations" — this plan supersedes
that sketch, which predates the website absorption: there is no
php-fpm and no separate JSON file anymore, radiod owns the site and
already persists settings in `/var/lib/radiod/state.toml`, reinstall-
proof). And yes: **favourites**, with a u — we're Canadian.

## The feature (per Stefan's spec)

- **Picking a favourite:** press **`f` while a station is playing** —
  the currently playing station joins the favourites list. Keyboard
  gesture in the spirit of the `t` theme cycler; explicitly "for now"
  (no keyboard on the iPhone PWA — a touch gesture or per-row toggle
  is a future iteration, not this plan).
- **Showing them:** when favourites exist, a channel list appears
  **above** the CHANNELS list, headed **`> FAVOURITES`**. Same table,
  same [PLAY] buttons, same [ON AIR] marker. No favourites → no
  section, the page looks exactly as today.

Proposed refinements (review points):

- **`f` toggles.** Pressing `f` on a station already in the list
  removes it — otherwise removal has no UI at all. Symmetric, and the
  section appearing/disappearing right under the cursor is its own
  feedback (action responses swap `#app` immediately).
- **Insertion order**, no sorting: it's *your* list, ordered by when
  you added things. The sort headers stay CHANNELS-only. The CH column
  reads `F1`, `F2`, … — a quiet nod to the future GPIO preset buttons
  ("favourite 1..4") in the ideas file.
- `f` does nothing while stopped, while AirPlay owns the pipe, or
  while typing in a field — same guards as `t`.

## Design

### The record

`notes/ideas.md` flagged this: store a **record, not a bare id**, so
adding non-SomaFM sources later never migrates the file. In
`state.toml`:

```toml
[[favourites]]
source = "somafm"
id = "dronezone"
```

v1 only ever writes `source = "somafm"`; unknown sources load fine and
render as nothing. Adding fields to a TOML table later is backward
compatible — that's the point of choosing a table over `"dronezone"`
strings now.

### Where it lives

Exactly the volume-persistence pattern:

- `Status` gains `favourites: Vec<Favourite>` (`#[serde(skip)]` — the
  JSON API contract is unchanged; exposing favourites over the API is
  a non-goal until something needs it).
- Loaded from `state.toml` at boot, seeded into the initial status.
- The existing 2 s state saver snapshots it; `save_if_changed` already
  makes idle sampling free.

The daemon stays a dumb player: favourites never touch the audio path
or the player thread — they are website/state concerns resolved
against the cached `channels.json` at render time, so titles, genres
and listener counts stay live, and a favourite whose id SomaFM stops
serving is skipped silently (kept in the file — outages happen).

### The action

`POST action=favourite` on the page (same form machinery as
play/volume): resolves the currently playing station's playlist URL to
a channel id via the cached channel list and toggles it. Not playing a
SomaFM channel (stopped, AirPlay) → the page re-renders unchanged.
POST-redirect-GET works like every other action, so this is usable
without JS too (via curl today, a row button some day); the `f` key is
just a JS shortcut that submits it (htmx swap of `#app`, preserving
the sort query like the existing forms).

### Rendering

Template gains a `favourites` list in the context (rows shaped like
`channels` rows). Non-empty → a `> FAVOURITES` section above
`> CHANNELS`, plain column headers (no sort links), `F1…Fn` numbering.
**A favourite appears in one list only** (review decision): stations
shown under FAVOURITES are removed from the CHANNELS rendering — no
duplicate rows. Only stations that actually render as favourites are
removed, so an unresolvable favourite never makes a channel vanish
from both lists. The playing row is marked wherever it lives. Hidden
entirely during AirPlay mode along with the rest of the tuner UI.

## Phases

One stack: this plan as the bottom PR, one implementation PR on top —
state + action + rendering + the `f` key are one cohesive change.

### Phase 1 — favourites

- `state.rs`: `Favourite { source, id }`, `favourites` in
  `PersistedState` (optional — old state files load), round-trip
  tests.
- `status.rs`: the skipped field; boot seeding in `main.rs`.
- `web.rs`: the `favourite` toggle action; favourites resolution in
  `render_page`; context + template + heading; `f` handler in
  `index.html` next to the `t` handler.
- `notes/plan.md`: the "Favorites/presets remain a future idea" line
  gets to retire.
- Tests: toggle adds then removes the playing station; no-op when
  stopped/during AirPlay; section renders above CHANNELS only when
  non-empty, with live channel data and [ON AIR]; unknown ids and
  unknown sources skipped; state file round-trips favourites;
  volume-only state files still load.

## Deferred UX issues (recorded at review, left for later)

Known and accepted for v1 — Stefan's call, on the record so they don't
get lost:

- **Not discoverable:** nothing on the page hints that `f` exists.
- **No remove affordance:** un-favouriting requires playing the
  station and pressing `f` again — there is no control on the list
  itself. A hover-revealed `[X]` per row was **built and rejected at
  review**: the extra column broke the two tables' identical look,
  and keeping FAVOURITES and CHANNELS visually the same table won.
  (Reverted in-branch; the history keeps the attempt.) Whatever
  removal control comes later must not change the table shape.
- **Not usable on mobile:** the iPhone PWA has no keyboard, so
  favourites can only be managed from a desktop browser (the list
  itself shows everywhere).

All three likely share one fix — some row-shape-preserving toggle —
tracked in `notes/ideas.md` ("Favourites UX iteration").

## Acceptance criteria

- Playing a station and pressing `f` makes it appear under
  `> FAVOURITES` at the top within the action swap; pressing `f` again
  removes it; the section is gone when the list is empty.
- Favourites survive `systemctl restart radiod`, a reboot, and a
  package upgrade (same `state.toml` guarantees as the volume).
- A favourites row plays its station with one click from the top of
  the page — the Drone Zone morning is one click.
- `cargo test`, `clippy`, `fmt` green; no new dependencies; JSON API
  unchanged.

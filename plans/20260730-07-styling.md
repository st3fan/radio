# Plan: Styling & polish (milestone 7)

Make the website look like something — specifically like **Phosphor**,
direction C from the style proposals: a green-phosphor CRT terminal.
Chosen by Stefan from three rendered mockups (Broadcast / Daylight /
Phosphor).

Two phases on `integration/milestone-7`: the stylesheet first, then the
live now-playing updates. Both stay within the site's rules: plain PHP,
no frameworks, no build step; JS is optional progressive enhancement.

## The Phosphor direction

- Palette: `#050805` ground, `#35E06B` phosphor, `#1F9C4D` dim,
  `#A7FFC4` highlight. Single-theme by definition — a CRT has no light
  mode (a deliberate exception to the both-themes default).
- Monospace everything (`ui-monospace` system stack — no webfonts),
  uppercase headings/labels, faint scanline overlay, subtle phosphor
  glow (`text-shadow`).
- No channel artwork — a terminal wouldn't. (The artwork column from
  milestone 5 goes away; the `image` data stays available in `lib/` if a
  future direction wants it back.)
- Controls as bracketed text: `[PAUSE] [STOP] [MUTE] [VOL+] [VOL-]`.
- Volume as an ASCII bar (`[██████░░░░] 25/50`) rendered by PHP from the
  effective volume and `max_volume`.
- Channels as a terminal table: channel number, station, genre,
  listeners (tabular numerals), `[PLAY]` per row; the playing row gets
  the highlight color and an `[ON AIR]` marker.

## Phase 1 — the stylesheet

- `website/public/style.css`, one hand-written file, linked from
  `index.php`; markup restructured only as far as the design needs
  (semantic classes, the table, the status block).
- `[VOL+]`/`[VOL-]` buttons: forms posting the current percentage ±10
  (clamped 0–100, computed server-side from the status) — coarse volume
  without typing a number; the number input stays as the precise
  control, styled as a terminal field.
- Responsiveness: readable from a phone across the office — the channel
  table drops the genre column under ~500 px, touch targets ≥ 40 px.
- Accessibility inside the aesthetic: phosphor-on-black contrast is
  ~10:1 (dim green reserved for secondary text), focus states as
  inverse-video blocks (the terminal idiom), and any blinking (the
  cursor) disabled under `prefers-reduced-motion`.
- Error/notice lines styled as terminal output (`! ERROR: ...`).

Tests/checks: `php -l`, manual pass on desktop + phone against the
daemon, the daemon-down and SomaFM-down pages still render in style.

## Phase 2 — live now-playing

- `website/public/status.php`: a ~10-line JSON proxy of the daemon's
  `GET /status` (the browser still never talks to the daemon).
- A small `website/public/radio.js` (vanilla, no dependencies): poll
  `status.php` every 5 s and update the now-playing block, state, and
  volume bar in place; a blinking block cursor after the song title as
  the "alive" indicator (CSS animation, reduced-motion gated).
- Progressive enhancement: without JS the page is exactly the phase-1
  site — forms and full-page reloads keep working; the poller touches
  only display, not controls.
- Bump the website package version to `0.2.0-1` and rebuild the .deb.

Acceptance (the finish line): on the Pi, from the Mac and from a phone —
the terminal UI renders, all controls work, the song title changes by
itself when SomaFM rotates tracks, and the whole thing still degrades
cleanly with JS disabled. `apt install` of the new .deb upgrades the site
in place.

## Out of scope

- Favorites/presets (future idea, unchanged).
- Any daemon changes — this milestone is website-only.
